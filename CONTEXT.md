# CONTEXT — доменная модель

Предметная область: учёт отсутствий сотрудников компании (до 500 человек) в соответствии с Трудовым кодексом РФ. Полные требования — `docs/requirements.md`, модель данных — `docs/plan.md`, раздел 4.

## Словарь: русский термин → идентификатор в коде

| Термин | В коде | Значение |
|---|---|---|
| Сотрудник | `employee` | Работник компании; карточка с кадровыми атрибутами (`FR-EMP-001`). |
| Подразделение | `department` | Узел оргструктуры (дерево), у каждого один руководитель. |
| Руководитель | — (`employees.manager_id`) | Не отдельная роль, а вычисляемый признак: тот, у кого есть подчинённые. |
| Учётная запись | `account` | Доступ в Систему: `auth_type` = `ldap` либо `local`, роль RBAC. |
| Вид отсутствия | `leave_type` | Настраиваемый справочник: отпуск, больничный, отгул, командировка и т.д. |
| Заявка на отсутствие | `leave_request` | Единая сущность для всех видов отсутствий, со статусами и маршрутом согласования. |
| Согласование (шаг) | `approval_step` | Этап маршрута: руководитель → HR. |
| Остаток отпуска | `leave_balance` | Начислено + ручная корректировка − использовано, по рабочему году. |
| Бизнес-день | `business_today` (параметр `business_timezone`) | Календарная дата «сегодня» Системы: текущий момент UTC, переведённый в часовой пояс ОРГАНИЗАЦИИ (по умолчанию Europe/Moscow, `BR-12`, `NFR-LOC-002`). От неё считаются начисление, остаток на дату по умолчанию, граница даты корректировки; метки времени (токены, блокировки, `updated_at`) бизнес-днём не являются и остаются в UTC. Тот же день - значение по умолчанию дат в интерфейсе: год производственного календаря и перечень годов, дата увольнения в карточке сотрудника (`NFR-LOC-002` v1.32); клиент берёт его из `GET /api/auth/me`. |
| Рабочий год | `working_year` | 12 месяцев от даты приёма сотрудника; не совпадает с календарным. |
| График отпусков | `vacation_schedule` | Плановый документ на календарный год (аналог формы Т-7), утверждает HRD. |
| Производственный календарь | `production_calendar_days` | Рабочие/выходные/праздничные дни по годам. |
| Отгул | `day_off` (вид отсутствия) | Компенсация переработки или работы в выходной; у сменных — в часах. |
| Компенсация за переработку | `overtime_ledger` | Накопленные часы/дни, из которых списывается отгул. |
| Больничный, ЭЛН | `sick_leave`, `document_number` | Временная нетрудоспособность; хранится только факт и даты, без диагноза. |
| Журнал аудита | `audit_log` | Неизменяемая история значимых действий. |
| Режим внедрения | — (`FR-AUTH-003`) | Работа без подключённого LDAP: все входят по e-mail и паролю. |

## Ключевые правила предметной области

Значения ниже — **настраиваемые параметры** (`business_rules_config`), а не константы в коде.

- Основной оплачиваемый отпуск — 28 календарных дней в год (ст. 115 ТК РФ).
- Право на первый отпуск — через 6 месяцев непрерывной работы (ст. 122).
- График отпусков утверждается не позднее 17 декабря на следующий год (ст. 123); уведомление сотрудника о начале отпуска — за 14 календарных дней.
- При разделении отпуска хотя бы одна часть — не менее 14 календарных дней (ст. 125).
- Отпуск используется не позднее 12 месяцев после окончания рабочего года (ст. 124).
- Больничный не уменьшает остаток основного отпуска; при пересечении с отпуском отпуск продлевается либо переносится.
- Командировка не расходует остаток отпуска, но отображается в календаре отсутствий.
- У сотрудников со сменным графиком (почасовая оплата) отгул учитывается в часах, вплоть до части смены; продолжительность основного отпуска от графика работы не зависит.

## Роли

`employee`, `hr_admin` (он же HRD — утверждает график отпусков), `accountant` (только чтение и выгрузки), `system_admin`. Права руководителя выводятся из наличия подчинённых, а не из значения роли. Матрица доступа — `docs/requirements.md`, раздел 7.

## Аутентификация

Основной способ — LDAP/Active Directory, сопоставление по корпоративному e-mail (`FR-AUTH-001`). Локальный вход по паролю — для служебных учётных записей, для отдельных сотрудников по решению HR и в режиме внедрения, пока каталог не подключён (`FR-AUTH-002/003`). Проверки доступа (карточка активна, учётная запись активна, роль назначена) — общие для обоих способов входа (`FR-AUTH-004`).
