# транзитивных, runtime и dev), закрепляющий прогон вне зависимости от
# того, какие версии были самыми свежими в момент установки.

# Сгенерирован внутри одноразового контейнера `--platform linux/amd64`
# (`pip-tools==7.4.1`, `pip-compile --extra dev --strip-extras`), а не на
# машине разработчика (arm64 macOS) и не внутри обычного dev-контейнера
# backend (на arm64-хосте он тоже aarch64) — у части пакетов состав
# зависимостей платформенно-условный, а раннер CI и прод — linux/amd64.
# Область применимости файла явно ограничена этой платформой: constraints
# только ОГРАНИЧИВАЮТ версию, если пакет вообще ставится, но не заставляют
# ставить пакет, нужный лишь на другой платформе — транзитивная
# зависимость, объявленная только под aarch64, в amd64-разрешённом файле
# отсутствовала бы вовсе и встала бы на arm64 без закрепления версии;
# расхождение было бы именно в версиях, а не только в конкретно собранных
# колёсах (wheels). На сегодняшнем графе зависимостей этого не произошло:
# `pip freeze --exclude-editable` внутри dev-контейнера backend на arm64
# (macOS) даёт ровно те же 62 имени, что и этот файл, 0 непокрытых в обе
# стороны — измерено 04.10.2026 (команда и вывод — PR #162 review,
# тело коммита). Это свойство ТЕКУЩЕГО графа зависимостей, а не гарантия
# на будущее: новая транзитивная зависимость, платформенно-условная под
# aarch64, может сделать файл неполным для arm64 и это не будет замечено
# ни одной проверкой в этом репозитории — `test_dependency_pins.py`
# проверяет только прямые зависимости (см. его докстринг), а CI прогоняет
# тесты исключительно на linux/amd64.
