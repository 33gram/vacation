# Декомпозиция задач (tasks.md) — Система учёта отпусков

**Версия документа:** 1.8
**Дата:** 18.09.2026
**Основание:** `requirements.md` v1.6 (функциональные/нефункциональные требования), `plan.md` v1.4 (архитектура, стек, этапы M0–M8)
**Статус:** Финальный артефакт SDD-цепочки (`requirements.md` → `plan.md` → `tasks.md`) — готов к исполнению разработчиками/AI-агентами.

**Как читать этот документ:**
- Задачи сгруппированы по этапам **M0–M8** из раздела 12 `plan.md`, внутри этапа — по слоям (модель данных → бизнес-логика/сервисы → API → frontend → тесты).
- Формат ID: `T-M{этап}-{номер}`. Порядок внутри этапа в основном последовательный; задачи с пометкой **[P]** можно выполнять параллельно с соседними (не имеют взаимных зависимостей).
- Каждая задача ссылается на функциональное/нефункциональное требование (`FR-XXX`/`NFR-XXX`) из `requirements.md` и на раздел `plan.md`, чтобы приёмка задачи проверялась напрямую по критериям EARS исходного требования.
- Задачи вида «Написать тесты на …» подразумевают покрытие **каждого** `WHEN/IF/WHILE/WHERE`-критерия соответствующего FR отдельным тест-кейсом (TDD-подход: тест пишется до или вместе с реализацией).
- Пути к файлам — согласно структуре репозитория, `plan.md` §3.
